# tribute-router

Принимает вебхуки аккаунта Tribute и пересылает каждое событие проекту-владельцу товара. Аккаунт Tribute один на все проекты, а у него один URL вебхука и один ключ подписи.

Событие уходит проекту тем же телом и тем же заголовком `trbt-signature`: проект проверяет подпись сам (ключ общий) и о маршрутизаторе не знает.

Ответы: 403 — неверная подпись; 502 — проект не принял событие, Tribute повторит доставку; 200 — остальное, включая неизвестный товар (в логе `tribute-unknown-product` с `alert`).

## Локальный запуск

```bash
cp apps/tribute-router/.env.example apps/tribute-router/.env
pnpm dev
```

Переменные — в `.env.example`.

## Как подключить проект или товар

1. Проект принимает `POST` с телом вебхука Tribute и сам проверяет `trbt-signature` тем же ключом.
2. Id нового товара добавить в env проекта и в `TRIBUTE_ROUTES`.
3. Перезапустить сервис.

## Деплой

- Dokploy, Dockerfile `apps/tribute-router/Dockerfile` от корня репозитория, порт 8000.
- Домен, например `tribute.<домен>`.
- В кабинете Tribute URL вебхука: `https://<домен>/tribute`.
