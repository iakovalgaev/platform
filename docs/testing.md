# О тестах

## — Зачем тесты? Я и так руками проверяю.

Пока проверяешь. А после следующего рефакторинга — снова. После апдейта схемы — снова. Собрать подписанный вебхук, отправить, повторить, попробовать с неверной подписью, с неизвестным товаром — 15 минут. Каждый раз. Навсегда.

Тест — та же ручная проверка, но записанная кодом. Написал один раз — машина повторяет её на каждый коммит.

## — Тогда давайте на всё напишем?

Тесты — это тоже код. Их тоже нужно поддерживать, читать при дебаге, разбираться с флейками. Плохо написанный тест ломается каждый раз, когда ты трогаешь соседний файл.

Правило одно: **тест должен окупать себя**. Защищать то, поломка чего стоит дороже, чем написание и поддержка теста. Проверка пересылки оплаты — окупается десять раз. Проверка "функция вернула число" — никогда.

## — А если TypeScript уже всё проверил?

Тогда тест не нужен:

```ts
function add(a: number, b: number): number { return a + b }
test("returns a number", () => {
  expect(typeof add(1, 2)).toBe("number") // бесполезно
})
```

Компилятор не даст вернуть строку. Единственный способ сломать — это сломать компиляцию.

Та же логика про остальной "воздух":
- **Внешние сервисы** — Tribute, Telegram. Чужой код тестировать бессмысленно, только свою обработку ответов.
- **Простой маппинг** — собрать объект, переименовать поля. Сломать незаметно невозможно.

## — Когда вообще писать тест?

Четыре сигнала. Хотя бы один подходит — пиши:

1. Код трогает деньги или доступ.
2. Баг уже был — чтобы не повторился.
3. Много ветвлений и граничных случаев, которые руками не перебрать.
4. Рефакторишь критичный модуль — тест фиксирует поведение до начала изменений.

Ни один не подходит — не пиши. Вернёшься, когда станет больно.

## Как пишем

Тест лежит рядом с кодом: `forward.ts` → `forward.test.ts`. Один файл — один сценарий. Открыл исходник, нажал `Cmd+P` с суффиксом `.test` — вот он.

Шаблон — три блока: подготовил, сделал, проверил.

```ts
test("пересылает событие проекту-владельцу товара", async () => {
  const app = await buildTestApp({ routes })
  const body = tributeBody({ productId: "42" })
  const fetchSpy = vi.spyOn(globalThis, "fetch").mockResolvedValue(new Response("ok"))

  const response = await app.inject({ method: "POST", url: "/tribute", headers: signedHeaders(body), payload: body })

  expect(response.statusCode).toBe(200)
  expect(fetchSpy).toHaveBeenCalledWith(routes[0].url, expect.objectContaining({ body }))
})
```

Мелочи, но важные:
- **Имя теста — про бизнес, на русском.** `"отвечает 403 на неверную подпись"`, не `"тест кейс 2"` и не `"вызывает findFirst дважды"`.
- **Одно действие на тест.** Хочется второй запрос — это второй тест.
- **Чистое состояние на каждый тест.** Приложение и подмены создаются в `beforeEach`. Никаких общих фикстур.
- **Assert на наблюдаемый результат.** Код ответа + исходящие запросы. Не внутренние вызовы функций; подменяется только внешняя сеть.
